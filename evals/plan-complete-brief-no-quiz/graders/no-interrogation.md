The brief already states the user, the need, the constraints, the technical choices and what done means. A successful response does not interrogate: it asks at most two clarifying questions, each about a fact only the user holds (for example the exact format of their files), and none about anything the brief already answers.

A list of assumptions the response has already made, which the user may correct, is not a list of questions and is fine.

Fail if the response withholds the plan until questions are answered, or if it re-asks something the brief states.
